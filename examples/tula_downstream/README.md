# tula_downstream

This project is the minimal package-consumer acceptance case:

```text
tula_downstream
└── requires tula-boilerplate/3.1.0
```

Build from a released package environment with:

```sh
./build
```

That one command bootstraps the pinned `tula-cmake` Python tool with `uvx`, runs
Conan, and uses the CMake preset generated by Conan.

An organization may pass shared Conan configuration through:

```sh
./build --config-source <git-directory-file-or-url>
```

For development in this workspace:

```sh
TULA_CMAKE_DEV_PROJECT=../.. ./build
```

The downstream recipe itself does not import `tula_cmake`; it is a conventional
Conan/CMake consumer of `tula-boilerplate`.
